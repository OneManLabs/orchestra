# Contribute to Orchestra

You can submit bug reports, proposals, documentation, and code.

Open an issue before you make a large change. Do not include these items:

- Credentials
- Private fleet data
- Sensitive logs
- Third-party material that you cannot distribute

## Code contributions

You must have the right to submit each contribution. Identify all third-party work and its license.

One Man Labs can require a contributor license agreement. This agreement lets the project use public noncommercial terms and separate commercial terms.

A pull request is not accepted until all required agreements are complete.

## Pull requests

- Keep the change small and focused.
- Explain the purpose and user effect.
- Add or change tests when behavior changes.
- Run `npm run verify` before review.
- Keep all copyright, attribution, and Required Notice lines.
- Report security problems as specified in [SECURITY.md](SECURITY.md).

## Documentation style

Use ASD-STE100 Simplified Technical English principles for project documentation.

- Use short sentences.
- Give one instruction in each step.
- Use active voice.
- Use the same term for the same item.
- Use American English spelling.
- Do not use slang or unnecessary synonyms.
- Keep command names, API names, and code identifiers unchanged.
